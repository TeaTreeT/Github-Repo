B1. Discover 5 unique weak/vulnerable security implementations.

1. Plaintext password storage
when a password is stored as..
password = "password123"
this is weak as if the database is leaked that means that all accounts are compromised. There is no protection against credential reuse attacks. A better approach would be to salt or hash the passwords.

2. Hardcoded Secrets in code
eg. API_KEY = "123456789SECRET"
Anyone with repo access can steal credentials and it's easily leaked in GitHub commits.
A better approach would be using environmental variables or secret managers such as AWS Secrets manager.

3. No input validation (XSS / injection risk)
eg. <div>User input: {{ input }}</div>
This allows injection of malicious scripts (XSS) and can lead to account hijacking or data theft
A better approach would be to sanitize and escape input or use frameworks that auto-escape output to ensure that there cannot be script injection attacks.

4. Overly permissive file permissions (Linux)
eg. chmod 777 file.txt
This allows for anyone to read/write/execute on a file and breaks access control principles.
To fix this make sure to the the least privilege principle.

5. No rate limiting on login systems
Unlimited login attempts.
This is bad as it enables brute force attacks and weak passwords could be cracked easy.
To fix this, add rate limiting and CAPTCHA or MFA.
